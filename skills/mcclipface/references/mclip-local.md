## Wish list and watch list (mClip Local)
- **Availability**: before first offer/chat GET /.well-known/oauth-authorization-server; non-200: accounts off; omit the account sentence. Any /api/local/* or /api/square/holds error (404, 503 too): silently skip; watch 404/503: no wish-list offers this chat; hold 404/503: say holds aren't available at that store yet.
- **Offer** once per user-deferred item: relay the watch reply's `say`, else: "Want me to add this to your wish list? We'll tell you about price drops, or if it's nearby and not online or cheaper there. Only anonymous counts are shared (no store sees counts; none shown under 25 people). Your wish list is saved for you. No account needed. An optional mClip account syncs it across devices and counts toward local deals." No yes: no add/send.
- **The list**: update user file (items/price lows/last wants send/area). No files: say unsaved; offer paste-back.
- **Watch list check-in** per user message/item: turn vague wants into coarse search terms (category+keywords); POST only item/category + area to /api/local/watch. POST /api/local/wants + client_install_id only on add/area change/after 30+ days. Area: current ZIP5/known metro/neighborhood; no ZIP3/coordinates/street/list. No area or unknown_area: skip silently. No background polls.
- **Price alerts (30/60/90-day lows)**: alert when a watch_notice item has alert_type price_low: "<item> is at a <window_days>-day low at <store>: <price> (typical <typical>)", window_days 30, 60 or 90 (the longest that holds; server-checked, at least 10% or $5 below typical). Save new lows; also alert on clearly lower comparable prices (online_deal/in_stock). Null price: name deal, no drop/amount.
- **Sale live** (deal_phase_live): a reminded store sale phase started; tell the user once with its phase text and dates, then run a lookup for links. Not a stock check.
- **In stock nearby** (in_stock): alert only if online unavailable (user checked, not empty results) or verified cheaper nearby. Ignore unknown `match_type`; confirm with user. Hold only with `hold_target` and mClip account (Bearer, scope `plus`); else mention the optional account; claim no hold. Ask once: "Do you want me to let the store know so they can hold it for you?" On yes: POST /api/square/holds JSON `{"consent":true,"hold_id":<new UUID, reused on retry>,"hold_target":<unchanged>,"quantity":1,"window_hours":<store's, else 24>}`. GET .../holds/{hold_id}; cancel POST .../{hold_id}/cancel `{}`. Poll per Retry-After in replies only; relay `say` exactly (state, reminders, limits; none: relay message).
- **mClip account** (optional, never required): mention it once after first add; coupons, deals and alerts never need it; no passwords. Counts at account age 7 days. Keep: one-way account ID/dates/list/ZIP-level area; no email/name/phone. Delete anytime. Yes: OAuth PKCE per metadata, scope wants:count plus; sync wants via Authorization: Bearer <token>, no install ID. "Help me set up my mClip account": ask setup questions, then connect via OAuth; accounts off or 404/503: relay `say` (none: "mClip accounts are coming soon! Your wish list still works on this device.")
